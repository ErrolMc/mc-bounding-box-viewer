# Bounding Box Viewer

Client-only Fabric mod for Minecraft 26.3: B toggles boxes around every structure within range (default 128 blocks across the ground): a thick outer box in the kind's colour, thinner boxes per piece, the spawn area shaded (from the structure's own `spawnOverrides`), and the name over the top. In singleplayer (or as LAN host) the structures come from the integrated server; on any other server (multiplayer, Realms) seed mode works them out from the world's seed. Covers every vanilla structure (`StructureKind`, grouped by dimension for the config screen) plus mod/datapack ones as `OTHER` with a colour hashed from the id. Config via Cloth Config + Mod Menu (optional). Built for the user's MultiMC instance at `E:\MultiMC\instances\26.3` (mods in `.minecraft\mods`). Set up like `..\light-level-overlay` and `..\blaze-spawner-finder` (same toolchain, test and VS Code conventions).

## How it works (checked in the 26.3 jar)

- Data: the client never gets structures from a server, so it reads the integrated server's (`StructureCollector`, server thread). `ServerChunkEvents.CHUNK_LOAD` gives each full chunk's `getAllStarts()`; its `getAllReferences()` name starts in other chunks, maybe unloaded, which are queued and read 8 per server tick (`LOADS_PER_TICK`) with `getChunk(x, z, STRUCTURE_STARTS, true)` + `getStartForStructure` (starts are saved at that stage, so this doesn't generate terrain). Everything is cleared on `SERVER_STARTING` / `SERVER_STOPPED`. Collection always runs, whether the boxes are on or not, so turning them on shows what's already loaded.
- Boxes: the outer box is `structure.adjustBoundingBox(union of the pieces' current boxes)` (`StructureInfos.bounds`), what `StructureStart.getBoundingBox()` gives after a reload. Not `getBoundingBox()` itself: it caches that on first call (at the references stage), but `ScatteredFeaturePiece`s (swamp huts, temples, igloos) and template pieces (shipwrecks, ocean ruins) move onto the ground when their chunk is decorated, so the cache keeps the planned height until the world reloads (seed 607's first swamp hut: planned y 64-70). `adjustBoundingBox` inflates by 12 when `terrainAdaptation() != NONE` (villages, outposts, strongholds, ancient cities, trail ruins, trial chambers). For the same reason, when a chunk loads with `generated` true (Fabric: it wasn't loaded back from disk as full, so it was just decorated), its starts are recorded again and its references to known starts are queued again (`QUEUED` dedupes the queue; `SEEN` stops unknown ones being looked for twice). Jigsaw pieces (`PoolElementStructurePiece`) use their template's box (`StructureInfos.pieceBox`): with `use_expansion_hack` (villages, outposts) the planner stretches some up to fit the pieces on top, which isn't saved, so a reloaded start has the template box (seed 607's outpost at chunk -16, 86: y 75-80 planned, 75-78 reloaded). The game's STRUCTURE-type spawn check (`StructureManager.getStructureAt`) uses the cached box, but outposts and monuments don't move, so it's the same box.
- `StructureStore`: per dimension, keyed by (structure id, start chunk), `ConcurrentHashMap` because the server thread writes and the client thread reads. Nothing is ever evicted within a world.
- Spawn area: `Structure.spawnOverrides()`; an override with an empty `spawns()` list only blocks spawns, so it's ignored. `BoundingBoxType.STRUCTURE` (outposts, monuments) shades the whole box; `PIECE` (swamp huts, fortresses) shades each piece.
- Drawing: vanilla gizmos, no custom render types or mixins. `BoxOverlay` rebuilds a `List<Gizmo>` every 5 client ticks (immediately on a dimension change or `rebuildSoon()`): `new CuboidGizmo(aabb, style, false)` per box and `new TextGizmo(pos, text, TextGizmo.Style.forColorAndCentered(argb).withScale(s))` per name (billboarded; scale / 16 world units per pixel; names grow with distance past 12 blocks so they keep their size on screen). `BoxRenderer` adds that list every frame from `LevelRenderEvents.BEFORE_GIZMOS` (fired just before `LevelRenderer.finalizeGizmoCollection`) inside `levelRenderer().collectPerFrameRenderThreadGizmos()`, with `Gizmos.addGizmo(g).setAlwaysOnTop()` when see-through is on. Not `DrawableGizmoPrimitives.submit(collector, camera, true)` from `COLLECT_SUBMITS`: the game only sets up its always-on-top pass (`frameHasAlwaysOnTopGizmos`, its own depth target) when its own list has always-on-top gizmos, so those submits were silently dropped (depth-tested ones worked).
- Range is horizontal distance from the eye to the box (any height), so strongholds and ancient cities under you count.
- Keys: `KeyMappingHelper.registerKeyMapping`, category `KeyMapping.Category.register(Identifier)`. B is unbound in vanilla 26.3. On a server with no seed known: a message, nothing turns on.
- Seed mode (`client/seed`): `VanillaWorldgen` loads the vanilla data pack's registries once, as `WorldLoader` does (`RegistryLayer.createRegistryAccess`, `TagLoader.loadTagsForExistingRegistries` + `buildUpdatedLookups`, `RegistryDataLoader.load(..., WORLD_REGISTRIES, ...)`, `replaceFrom(WORLD, ...)`), plus a `StructureTemplateManager` over the same resources (with a throwaway temp world folder). `SeedWorld` takes the world preset's `LevelStem`s; `SeedDimension` sets up generator, `RandomState` and `ChunkGeneratorStructureState` as `ChunkMap` does, and `plan(x, z)` replays `ChunkGenerator.createStructures` (single entry, or weighted pick with `setLargeFeatureSeed` and retry). Planning is exact. `SeedSettling` estimates the pieces that move when decorated (swamp hut / jungle temple average `MOTION_BLOCKING_NO_LEAVES` over the piece in its start chunk; desert pyramid lowest minus the start chunk's decoration random `nextInt(3)`; igloo `WORLD_SURFACE_WG` at the entrance; shipwreck mean / beached lowest; ocean ruin `Settling.oceanRuin`; buried treasure `OCEAN_FLOOR_WG - BURIED_TREASURE_DEPTH`), terrain only, start chunk decorated first. `SeedMode`: on `JOIN` to a non-singleplayer server, the seed saved under `ServerKey` (Realm by name, server by address minus `:25565`) in `BoxConfig.seeds`; with the boxes on, 1-3 low-priority worker threads plan chunks ring by ring within `ceil(range / 16) + REACH_CHUNKS` (8), at most 128 in flight, into `StructureStore`; an epoch drops work for an old seed; `idle()` once all in range are done; buried treasure is moved onto the client chunk's chest. `SeedSnapping` puts the other settling structures on the client's real blocks: once all the chunks under a start are on the client (retried each time more of them are; nearest first, one thread, 2 at once: `SeedMode.TO_SNAP`), the start is planned again and each settling piece built into a stand-in `WorldGenLevel` (a `java.lang.reflect.Proxy` keeping `setBlock`s: stone below the planned bottom, heightmaps there, `getLevel()` throws so no mobs; a template with only its `BlockIgnoreProcessor`s, once per palette, as the game picks the palette from `Mth.getSeed` of where the template ends up so it changes with the height tried), then slid up to 64 up and down over the client's blocks to where most match (mossy / cracked / chiseled / suspicious / infested count as the plain block, any air as air); found with at least 8 solid blocks matching and half of those that can be read. An igloo moves as a whole by its top. A piece's blocks aren't always all at one height: the game places it a chunk at a time and can work its height out again for a later chunk, over what the chunks before put down. Ocean ruins always do. Shipwrecks and scattered pieces save that they did (`height_adjusted`, `HPos`), but moving a piece doesn't mark its start chunk unsaved, so a dedicated server that lets that chunk go and reads it back does it again. The server's box is the last time's, the snap where most of the blocks are. `SeedCommands`: `/boxes seed [<seed> [type] | clear]` (Fabric client commands) and `/seed`'s reply (`commands.seed.success`, arg `[n]`) from `ClientReceiveMessageEvents.GAME`.

## Gotchas

- Needs JDK 25; `gradle/gradle-daemon-jvm.properties` makes the wrapper use it although `JAVA_HOME` is JDK 17.
- 26.x is unobfuscated Mojang names: `Identifier` (not `ResourceLocation`), `ResourceKey.identifier()`, `ChunkPos` is a record (`x()`, `z()`, `pack()`, `unpack(long)`, `getX(long)`, `ChunkPos.containing`), `player.sendOverlayMessage`.
- Loom plugin is `net.fabricmc.fabric-loom` (no remapping): plain `implementation`/`compileOnly`/`localRuntime`.
- `StructureKind.of` only maps `minecraft:` ids, by key or key + `_variant` (`village_plains`, `abandoned_camp_cherry_grove`, `ruined_portal_nether`); anything else is `OTHER`. A new vanilla structure needs a kind, a lang entry and a line in `StructureKindTest`.
- Game tests: load chunks inside `computeOnServer` with `getChunk(x, z, STRUCTURE_STARTS, true)`; reset `BoxConfig` fields at the start (`TestWorlds.resetConfig`: the test client reads the dev run's `config/bounding-box-viewer.json`; drops seeds saved for `server:localhost*`).
- Fabric's dedicated test server only starts with `eula = true` in `fabricApi.configureTests` (the user accepted the Minecraft EULA for it).
- Fabric's dedicated test server runs in this JVM, so Fabric's server events fire for it too: `StructureCollector` ignores `isDedicatedServer()` servers, or it would fill the store from the server and hide seed mode's mistakes. Its world comes from the create-world screen (`worldBuilder().adjustSettings(...).createServer()`); the player isn't an operator until `op @a`.
- `ClientLevel.hasChunk` is always `true` in 26.3, and `ClientLevel.getChunk` gives an empty stand-in (all `void_air`) for a chunk the client hasn't got: use `SeedMode.clientChunk` (`getChunkSource().getChunk(x, z, FULL, false)`, null when missing).
- Chunk statuses in 26.3: `EMPTY, STRUCTURE_STARTS, STRUCTURE_REFERENCES, BIOMES, TERRAIN, FEATURES, ...`; `FEATURES` on a chunk decorates only it (needs `TERRAIN` around it).
- IDE is VS Code. `.vscode/launch.json` is hand-written; don't run `gradlew vscode`.

## Layout

- `src/main`: `structure/` is pure Java (no Minecraft), unit tested in `src/test`: `Box` (inclusive block corners, distances), `StructureKind` (id → kind, variant, colour), `SpawnArea`, `Settling` (ground-height maths), `SeedText` (seed text and `/seed`'s reply), `WorldType`, `ServerKey`.
- `src/client`: `world/` (`StructureCollector`, `StructureStore`, `StructureInfo`, `StructureInfos`); `seed/` (`VanillaWorldgen`, `SeedWorld`, `SeedDimension`, `SeedSettling`, `SeedSnapping`, `SeedMode`, `SeedCommands`); `overlay/` (`BoxOverlay` lays out, `BoxRenderer` submits, `Labels`); `input/BoxKeys`; `config/` (`BoxConfig` Gson, `ConfigScreen` Cloth Config, `ModMenuIntegration`). No mixins.
- `src/gametest`: `BoundingBoxViewerClientGameTest` (singleplayer, every structure), `SeedPlanningClientGameTest`, `SeedServerClientGameTest`, shared `TestWorlds` and `SeedCompare`, `MuteAudio`, `ChunkSaving` + `mixin/ChunkMapMixin` (test-only mixin config `bounding-box-viewer-gametest.mixins.json`; the mod itself has none), and the survey's `SeedSurvey` and `SeedSurveySummary`. All three are entrypoints in `src/gametest/resources/fabric.mod.json`, run in that order.
